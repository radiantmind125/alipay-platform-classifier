# SSP 上线配置说明(两条检测线)· 2026-08-05

## 一句话
**v6 抓"整张 AI 生成"**(豆包/千问/Flux/SD3 都 0 漏检), **局部检测器抓"只改金额"**(白底账单详情页 ~92%)。
两条都按经理定的**只挑不拒**接入: 命中 = 进人工复核, **模型永不直接拒绝用户 → 结构上不会误杀赔钱**。

**模型**: `snapshot\aigen_v6\Net_epoch_best.pth`
**调用**: `predict_all_models.py`(整图打分)
**阈值**: Reject ≥0.90 / ManualReview 0.60-0.90 / Pass <0.60

| 测试集 | 漏检 | 高置信拦截 |

| Flux | 0% | 88% |

## 线路 B · 局部改金额检测(localdet)

**模型**: `snapshot\localdet\Net_epoch_best.pth`
**调用**: `predict_tiled.py`
**参数(实测最优, 别改)**:
```
--roi-amount --amount-pad 0 --skip-blue --agg max --roi-top 0.6
```
**阈值: `tile_max >= 0.9911`** → 进人工复核。
**出信号的前提**: 金额定位成功 且 不是蓝图。**否则这条线不出信号**(不是"判真", 是"无意见", 交给线路A和业务核验)。

| 测试集 | tile_max 召回 @~0.2%误杀 |
|---|---|
| SD-VAE-mse 未见图 | 87.5% |
| SD-VAE-ema 未见生成器+未见图 | 92.5% |
| **真 Seedream(真实服务 不同架构)** | **92.6%** |
| (对照)v6 整图打分 | **0%** |
| (对照)v6 + 分块 | 33.3% |

**为什么必须用 `max` 不用 `mean`**: 两者在 SD 族上打平(92.5 vs 92.2), 但**在真 Seedream 上 max 92.6% 而 mean 只有 83.3%**。只有 max 两个测试都稳。

## 覆盖范围(必须如实说)

| 版式 | 占真图样本 | 线路A(整图AI) | 线路B(局部改金额) |
|---|---|---|---|
| 白底账单详情 | ~35% | ✅ | ✅ ~92% |
| 蓝底转账页 | ~36% | ✅ | ❌ **没有**(金额是白字蓝底, 现有定位器看不见) |
| 其他/定位失败 | ~28% | ✅ | ❌ 没有 |

**所以"局部改金额抓 92%"只对白底账单详情页成立, 不是整体数字。**
蓝图要补局部覆盖, 需要**蓝图专用的金额定位器**(白字蓝底) —— 正好对应经理"蓝白分开标位置 共用识别器"的计划, 可与 OCR 那条线共用标注。

## 已知短板(别对外承诺过头)
1. **重压缩的假图**: 假图被反复转发压缩后, 高频指纹被压掉 → 线路A 识别率下降(实测微信双压后从 95% 降到个位数硬拦, 但仍有约九成进复核)。这是这类检测器的硬限, 训练救不回(v4b 验证过)。
2. **蓝图无局部覆盖**(上表)。
3. **传统非AI篡改**(复制粘贴/重打数字)**未测** —— localdet 是按"AI 重绘过的块"训的, 对纯手工改字未必有效。要覆盖得另做(传统取证特征 ELA/噪声不一致/JPEG ghost)。
4. 局部检测器的真实服务测试只有 **54 张**(92.6% = 50/54, 约 ±7%)。结论稳, 具体数值别报太精确。
5. 误杀标定基于 **952 张**白图真图 → 只能分辨到 ~0.2% 量级。

## 上线后要做的
- 收集人工复核的判定结果, 回流校准阈值(线上分布和测试集不会完全一样)。
- 持续按经理的方向**新增生成器**; 有新的国内模型(可灵/万相等)先按现有流程测覆盖, 漏了再加训练。
- 监控误杀: 任何一版改动上线前, 误杀不得高于当前基线。
